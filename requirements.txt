# via the `libmagic1` system package (see .github/workflows/eval.yml) — no

# for Linux anyway. Windows has no libmagic system package, so it needs this
# bundled wheel instead; without it, DocumentParser().parse() segfaults/
# crashes native-side deep inside unstructured's file-type detection rather
# than raising a catchable Python exception.

# LLM & Embeddings
# NOTE: openai==1.35.3 (the version originally pinned here) passes a
# `proxies` kwarg to httpx.Client.__init__() (src/common/llm_client.py's
# OpenAI/DeepSeek adapters both hit this at client construction). httpx>=0.28
# removed that kwarg, breaking every LLM call in the pipeline with
# "Client.__init__() got an unexpected keyword argument 'proxies'". Bumped to
# the latest 1.x release (still pre-2.0, no breaking API changes for the
# plain chat-completions usage in llm_client.py) since that fixed the httpx
# incompatibility — this also removes the need to pin httpx down, which
# matters because google-genai (below) hard-requires httpx>=0.28.1.
openai==1.109.1
# Bumped from 0.7.2: that version pulls in google-ai-generativelanguage<0.7,
# which caps protobuf<5.0dev — conflicts with streamlit==1.61.0's
# protobuf>=5.26.1 requirement (see Observability section below). 0.8.6
# pulls in google-ai-generativelanguage==0.6.15 (protobuf<6.0dev,>=3.20.2
# — overlaps with streamlit's range) and keeps the same `genai.GenerativeModel`
# API GeminiAdapter uses (src/common/llm_client.py), just with a
# FutureWarning that the classic google.generativeai package is deprecated
# in favor of google.genai — not acted on here, out of scope for this change.
google-generativeai==0.8.6
# Two distinct, differently-named Google SDKs are both required — they were
# never actually compatible substitutes for each other:
# - google-generativeai: src/common/llm_client.py's GeminiAdapter
#   (`import google.generativeai as genai`, `genai.GenerativeModel(...)`).
# - google-genai: src/ingestion/embedder.py's GoogleProvider, the default
#   embedding provider (`from google import genai`, `genai.Client(...)`) —
#   this package was missing from requirements.txt entirely, so the default
#   embedding path (gemini-embedding-001) could never actually run.
google-genai==2.16.0
